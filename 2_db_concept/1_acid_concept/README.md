## Question
- 1_acid_concept: อธิบายหลักการ ACID
![](/assets/q_acid.png)
## Response Section

ACID Concept คือ ชุดคุณสมบัติ 4 ประการที่ใช้รับประกันความน่าเชื่อถือและความถูกต้องของการทำธุรกรรม (Transaction) ในระบบจัดการฐานข้อมูล (DBMS) เพื่อป้องกันไม่ให้ข้อมูลเสียหายหรือเกิดความผิดพลาดเมื่อมีการอ่านหรือเขียนข้อมูลพร้อมกัน
Atomicity (ความเป็นอะตอม): ทำงานแบบ "ทั้งหมดหรือไม่มีเลย" (All-or-Nothing) หากมีขั้นตอนใดขั้นตอนหนึ่งใน Transaction ล้มเหลว ระบบจะทำการยกเลิก (Rollback) ทุกขั้นตอนที่ทำไปก่อนหน้าทั้งหมด เช่น การโอนเงินที่มีการตัดเงินบัญชี A แต่เข้าบัญชี B ไม่สำเร็จ ระบบต้องยกเลิกการตัดเงินบัญชี A ด้วย [] (https://medium.com/@chutdanai.tho/acid-%E0%B8%99%E0%B8%B1%E0%B9%89%E0%B8%99%E0%B8%AA%E0%B8%B3%E0%B8%84%E0%B8%B1%E0%B8%8D%E0%B9%84%E0%B8%89%E0%B8%99%E0%B9%83%E0%B8%99-transactional-database-part-1-a7aa502f1569)[] (https://translate.google.com/translate?u=https://motherduck.com/learn/acid-transactions-sql/&hl=th&sl=en&tl=th&client=sge)
Consistency (ความสอดคล้อง): ข้อมูลต้องอยู่ภายใต้กฎเกณฑ์และข้อกำหนด (Constraints) ของฐานข้อมูลเสมอ ก่อนและหลังทำ Transaction ข้อมูลจะต้องไม่ขัดแย้งกับกฎของระบบ เช่น ห้ามมียอดเงินในบัญชีติดลบ [] (https://translate.google.com/translate?u=https://motherduck.com/learn/acid-transactions-sql/&hl=th&sl=en&tl=th&client=sge)
Isolation (การแยกตัว): การทำ Transaction ที่เกิดขึ้นพร้อมกันจะต้องไม่ก้าวก่ายหรือส่งผลกระทบต่อกัน เปรียบเสมือนว่าแต่ละ Transaction ทำงานแยกออกจากกันโดยลำพัง เพื่อป้องกันปัญหาอ่านข้อมูลที่ยังไม่สมบูรณ์ (Dirty Read) [] (https://translate.google.com/translate?u=https://motherduck.com/learn/acid-transactions-sql/&hl=th&sl=en&tl=th&client=sge)
Durability (ความคงทน): เมื่อยืนยันการบันทึกข้อมูลเรียบร้อยแล้ว (Commit) ข้อมูลนั้นจะถูกบันทึกไว้อย่างถาวร แม้ว่าระบบจะเกิดไฟฟ้าดับหรือเซิร์ฟเวอร์ล่มทันทีหลัง Commit ข้อมูลก็จะไม่สูญหาย

ตัวอย่าง Atomicity เช่น หาก นาย จตุพรต้องการโอนเงิน 1000 ให้แม่
1 หักเงินจากบัญชี จตุพร 1000  บาท
2 แม่ได้รับ 1000 บาท
3 เสร็จสิ้น
แต่หาก จ่ายเงินจากบัญชีผิดพลาด
1 หักเงินจากบัญชี จตุพร 1000  บาท
2 ผิดพลาด
ระบบจะต้องสามารถทำให้เงินของนายจตุพร เท่าเดิม ต้อง Rollback Transaction กลับมาได้

Consistency  ตัวอย่างเงินในบัญชีห้ามติดลบเช่น
นาย จตุพรมีเงินติดตัว 0 บาท ได้แต่ไม่มีทาง เป็นเงิน -1000 บาทเป็นต้น

Isolation คือหลักการที่กำหนดว่า เมื่อมีหลาย Transaction ทำงานพร้อมกัน แต่ละ Transaction จะต้องไม่รบกวนกันจนทำให้ข้อมูลเกิดความผิดพลาด
ตัวอย่างเช่น นายจตุพรมีเงินในบัญชี 1,000 บาท และมีการทำรายการพร้อมกัน 2 รายการ
Transaction A ต้องการจ่ายเงิน 500 บาท
Transaction B ต้องการจ่ายเงิน 500 บาท
ถึงแม้ Transaction ทั้งสองจะเข้ามาในเวลาเดียวกัน ระบบฐานข้อมูลจะต้องจัดการไม่ให้ทั้งสอง Transaction อ่านหรือแก้ไขข้อมูลในลักษณะที่ทำให้ยอดเงินผิดพลาดหรือทำให้รายการใดรายการหนึ่งสูญหาย
เมื่อทั้งสอง Transaction สำเร็จ ยอดเงินที่ถูกต้องควรเหลือ 0 บาท

Durability ตัวอย่างหากข้อมูลบัญชีลูกค้าขึ้น Server ไปแล้วข้อมูลนั้นจะคงทนและไม่หายไป เช่นนาย จตุพร มีเงินในบัญชี 10 ล้านจะมาบอกว่า Server  ล้มและข้อมูลหายไม่ได้
